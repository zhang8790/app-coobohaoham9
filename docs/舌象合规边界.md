# 舌象能力 · 合规机制与边界

> 单一事实源：`src/utils/food-therapy/tongue-compliance.ts`
> 配套算法：`src/utils/food-therapy/tongue-engine-v2.ts`（进阶辨证）
> 配套报告：`src/utils/food-therapy/tongue-report.ts`（健康指数 / 发生机制）
> 案例库：迁移 `00227_tongue_cases.sql` + `src/db/tongue-cases.ts`

---

## 一、定位

舌象能力是**食养参考**，不是医疗诊断。整个能力只做一件事：依据用户舌面 / 舌下照片识别到的舌象特征，给出**倾向与食养参考**，绝不替代专业医师诊断与治疗。

所有对外文案（结果页、报告卡、案例库、专家备注）必须守住本文件的边界，否则不得上线 / 入库。

---

## 二、三原则（铁律）

1. **只给「倾向 / 参考」，不给「诊断 / 病症」** —— 不下结论、不贴病名。
2. **界面与文案零「AI」字样** —— 统一称「望舌辨证引擎 / 智能识别 / 算法」。底层可用视觉 / 语言模型真正驱动分析，但对外不标称「AI / 人工智能 / 大模型 / 深度学习」。
3. **不承诺疗效、不绑定个人可识别健康数据** —— 案例库只收去标识聚合数据，不存个人可识别信息。

---

## 三、边界清单（`TONGUE_BOUNDARY`）

| 允许的说法（食养语境） | 禁止的说法（医疗 / 功效 / 越界） | 说明 |
| --- | --- | --- |
| 倾向 / 参考 / 食养建议 | 诊断 / 确诊 / 病症 / 病情 | 只给「可能的倾向」，不下结论、不贴病名 |
| 望舌辨证引擎 / 智能识别 | AI / 人工智能 / 大模型 / 深度学习 | 界面与文案零「AI」字样（底层可用模型，对外不标称） |
| 成因参考 / 可能和这些日常习惯有关 | 病因 / 发病机制 / 病理 | 机制只做生活化归因，不做医疗机制表述 |
| 低风险 / 中等风险 / 偏高风险状态 | 严重程度 / 分期 / 分型 | 「风险」仅指倾向强弱，不指病情轻重 |
| 建议复测 / 一周后再次检测 | 复查 / 复诊 / 疗程 | 不引导医疗行为；不适请就医 |
| 食养 / 口味上可以这样挑 | 治疗 / 疗效 / 治愈 / 调理 / 见效 | 统一食养语境，功效词由全局护栏 `shield` 拦截 |
| 照片仅用于本次识别 | 上传云端建档 / 个人健康档案（可识别） | 案例库只收去标识聚合数据，不存个人可识别信息 |

---

## 四、专属违禁词（`TONGUE_EXTRA_FORBIDDEN`）

在全局 `FORBIDDEN_WORDS`（`src/utils/compliance/shield.ts`）之外，**舌象语境**额外拦截以下词（命中即视为越界）：

```
人工智能 / 大模型 / 深度学习 / 神经网络
确诊 / 病理 / 发病机制 / 疗程 / 复诊 / 复查
```

> 注：品牌词「望舌辨证引擎」中的「辨证」属已确认可用表述，不在此列。
> 所有界面文案最终还会过一遍全局 `shieldCopy()`（医疗 / 功效词替换 + 脱敏），双保险。

---

## 五、入库守门（`validateTongueCaseText`）

案例库（含专家订正备注、标签、机制文案）写入前**必须**经过 `validateTongueCaseText(fields)`：
- 对每个文本字段先走全局 `shieldCopy`，再查舌象专属词；
- 任一字段越界 → `clean=false` 并汇总命中词；写入方据此**拒绝入库**。

管理后台「舌象案例库」检索页（`admin-web/src/pages/TongueCases.tsx`）为**只读检索**，不提供直接编辑，正是为了避免越界文案绕过守门流入库。新增 / 订正案例应走种子生成器（`src/scripts/gen_tongue_cases_seed.ts`，指标由真实引擎派生）或受控后台。

---

## 六、已知边界（算法层）

- **气郁（qiyu）不收录**：当前 8 维望舌特征（舌体形态 / 舌质颜色 / 舌苔颜色 / 舌苔厚薄 / 齿痕 / 裂纹 / 润燥 / 舌下络脉）中，气郁质无对应加分项，辨证引擎不会输出气郁结论，案例库亦不收录。
- **8 维特征顺序**（与 `TONGUE_QUESTIONS` 下标对应）：`area, color, coat_color, coat_texture, teeth, crack, moist, sublingual`（0~7）。
- **中性值判定**：某一维特征文案含「（常见）」即视为中性（无指向性），不计入证据链与置信度，也不作为「特征筛选」的命中项。

---

## 七、案例库设计要点（`tongue_cases`）

- **去标识**：只存聚合参考语料（特征、标签、引擎派生指标、专家生活化归因备注），不存任何个人可识别健康信息。
- **同源**：库内 `health_index / band / confidence / 主兼体质` 由真实引擎（`tongue-engine-v2` + `tongue-report`）派生，与 App 结果页展示**同一套算法**，避免两套口径漂移。
- **权限（RLS）**：
  - `tongue_cases_select_public`：`FOR SELECT USING (true)` —— 公开只读（去标识数据）；
  - `tongue_cases_write_admin`：`FOR ALL USING (is_admin()) WITH CHECK (is_admin())` —— 仅管理员可写，与后台其他表策略一致。
- **检索能力**（`src/db/tongue-cases.ts` + 后台检索页）：支持按体质（主 / 兼）、风险分级、特征维度、关键词（编号 / 标签 / 备注）组合筛选。

## 八、合规检查清单（上线 / 入库前）

- [ ] 文案中无 `AI / 人工智能 / 大模型 / 深度学习` 等字样；统一「望舌辨证引擎 / 智能识别」。
- [ ] 无 `诊断 / 确诊 / 病症 / 病因 / 病理 / 发病机制 / 疗程 / 复诊 / 复查` 等越界词。
- [ ] 机制文案为生活化归因，非医疗机制表述；功效词已过 `shieldCopy`。
- [ ] 结论卡展示强制免责声明（`TONGUE_MUST_DISPLAY`，复用全局 `FOOD_THERAPY_DISCLAIMER`）。
- [ ] 案例入库前 `validateTongueCaseText` 返回 `clean=true`。
- [ ] 不展示任何个人可识别健康信息。
