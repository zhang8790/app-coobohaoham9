### 1.2 为什么「微传媒」不能独立建模块

原文档要求微传媒有自己的首页、自己的编辑器、自己的历史列表、自己的底部导航（主页/我的/新建/返回），并与创作中枢「双向打通」。

**这是把一个按钮做成了一个 App。** 实际后果：

- 两套编辑器 → 两套排版规则 → 同一篇图文两边打开显示不一致，草稿互导必丢格式；
- 两套历史列表 → 用户永远搞不清「我的文章」在哪一边；
- 小程序包体积紧张，多一套底部导航纯浪费；
- 「双向打通」需要一层格式中间层，工作量比编辑器本身还大。

**正确形态：微传媒 = 创作中枢里的一个入口 + 编辑器里的一个按钮。**

```
创作中枢（tabBar 中间 ⊕）
├── 快发 · 心情配方卡      ← 已有，30 秒出图，轻量路线
├── 深创 · 写图文           ← 块编辑器，本 PRD 主体
│     └── 工具栏：[📥 素材工坊] [🛒 好物卡] [⚠️ 免责声明] [📄 模板]
├── 素材工坊                ← 微传媒「链接解析首页」降维成这一项
│     └── 粘贴链接 → 版权弹窗 → 解析 → 落草稿箱 → 直接进「深创」
├── 我的创作                ← 草稿箱 / 已发布，唯一内容管理入口
└── 心情广场
```

素材工坊**不产出成品，只产出草稿**——既满足原文档「素材抓取仅获取草稿，不允许一键原样发布」的风控要求，又天然消灭双编辑器问题。

### 1.3 必须纠正的产品假设：小程序没有「文章链接」

原文档反复出现「生成独立永久链接」「复制文章链接发朋友圈」「文章下架后外部链接失效」。

**微信小程序页面不存在可在微信外打开的 URL。** 事实约束：

- 朋友圈**无法直接发小程序卡片**，只能发图片；用户进入只能**长按识别海报上的小程序码**；
- 所谓「独立链接」在小程序里只能是页面路径 `/pages/content/article-detail/index?id=xxx&ref=xxx`，仅在微信内、且必须经分享卡片或扫码进入；
- 真要对外 URL，必须另做 **H5 镜像站**（独立域名 + 备案 + SSR + 小程序码回流），是另一个项目。

**处理方式**：
- 「朋友圈方案 B（复制链接）」→ **删除**，替换为「保存海报到相册」；
- 「独立永久链接」→ 落地为**页面路径 + `ref` 归因参数**，功能等价；
- 「下架后链接失效」→ 落地为**详情页读到 `is_published=false` 渲染「该内容已下架」占位页**，效果等价。

### 1.4 命门：文章 → 好物卡 → 订单 → 佣金 的归因链现在是断的

这是整套「内容锁客」方案里**唯一决定成败**的东西，而它断了三处：

| 断点 | 现状 | 后果 |
|---|---|---|
| ① 分享参数不统一 | `useShareWithReferral` 用 `ref=`，「我的创作」用 `from=`，详情页只认 `ref`/`inviter` | 从「我的创作」分享出去的图文，**推广关系全部丢失** |
| ② 锁客函数被 store_id 挡死 | `lockCustomerByArticle(storeId, code)` 开头 `if (!storeId) return`，而 `articles` 表**根本没有 store_id 列** | 文章归因 **100% 不执行** |
| ③ 商品页丢弃来源参数 | 好物卡跳转带 `&from=article&articleId=xx`，但 `product/index.tsx` 只解析 `id/ep/batch`；`create-order` 无 source 入参；`orders` 无 `article_id` | **无法统计一篇文章带来多少订单**，埋点章节直接落空 |

①② **本轮已修复**（见第六章）。③ 需建表 + 改下单链路，列 P1——**没有 ③ 就没有「发文章看得见收益」的激励闭环，推广侠客不会持续创作。**

### 1.5 定位纠偏：不要做「文章劫持工具」

原文档把本质定义为「抓取外网优质内容，二次加工植入自家推广入口」。这个定位在微信生态里是**三重红线**：

1. **版权**：批量搬运公众号/小红书，被投诉即下架，严重者小程序封禁；
2. **诱导分享**：「分享得金豆」若做成强制/诱导（如「不分享不能看」），违反《微信小程序运营规范》；
3. **食品广告**：借来的原文本身带「降压/润喉/养胃」功效词，搬进来即违法。

**安全定位：素材工坊是「灵感参考工具」，不是「搬运工具」。** 产品层强约束：

- 导入内容**只进草稿**，不可一键发布；
- 导入后**必须改写**：一期做**改写率闸门**——发布时与原始素材比对，**Jaccard 相似度 > 60% 拦截发布**，提示「请用自己的话重写」；
- 导入正文**先过 `shieldCopy()` 洗一遍**，功效词进编辑器前就被替换，从源头断绝违规；
- 保留 `source_url`，后台可溯源。

### 2.2 素材工坊（🆕）

**布局**
- 输入框：`粘贴公众号 / 小红书 / 视频号文章链接`
- 提示：`素材仅作为创作参考，请勿直接搬运发布`
- 按钮：`清空`、`解析`
- 辅助：`使用指南`（跳 SOP 页）

**交互**
1. 点「解析」→ **强制弹窗**（每次必弹，不可记住）：
   > 【重要声明】
   > 抓取内容仅作为创作素材参考，直接转载他人原创内容存在版权侵权风险，请大幅度改写文案、替换图片后再发布。用户对发布内容版权承担全部责任。

   按钮：`我已知悉，继续解析` / `取消`
2. 调 `article-fetch` → `{title, content, images, videos}`
3. 正文过 `shieldCopy()` 洗违禁词 → 落草稿（`is_published=false`，记 `source_url` + `source_fingerprint`）
4. 结果页两个出口：`去改写`（进深创编辑器带 `articleId`）/ `存草稿箱`

**失败兜底**：公众号、小红书反爬普遍失败（现网实测）。失败时**不报错**，改为引导：
> 该平台不支持自动提取。请在原文长按「全选 → 复制」，粘贴到下方输入框，我帮你排版。

提供大文本框接手动粘贴，走同一条洗词 + 落草稿链路。**这条兜底比解析本身更重要**——它保证功能永远可用。

### 2.3 深创编辑器：块编辑器（不是富文本）

**为什么不做 contenteditable 富文本**：小程序 `<rich-text>` 只读不可编辑，`<editor>` 组件（wx 基础库 2.7+）在 Taro 下坑多、样式不可控、复制粘贴丢格式、无法内嵌自定义好物卡组件。强行做，工期 ×3，稳定性 ÷3。

**块编辑器方案**：正文 = 有序的块数组，每块一种类型，序列化成现有 token 文本存 `articles.content`（**不改表结构，与现有详情页解析完全兼容**）。

| 块类型 | 编辑态 | 序列化 token |
|---|---|---|
| 段落 | 多行输入框 | 纯文本 |
| 标题 | 单行输入框 + H1/H2 切换 | `[[h1:文字]]` / `[[h2:文字]]` |
| 图片 | 缩略图 + 换图/删除 | `[[img:URL]]` ✅已支持 |
| 好物卡 | 商品缩略卡 | `[[product:ID]]` ✅已支持 |
| 引用 | 输入框（左侧竖线样式） | `[[quote:文字]]` |
| 分割线 | 一条线 | `[[hr]]` |
| 免责声明 | 固定文本，不可编辑，可删 | `[[disclaimer]]` |

每块右上角：`↑ ↓ ✕`（上移/下移/删除）——这就是原文档要的「图文拖拽调整顺序」，用按钮实现，比拖拽在小程序里稳得多。

底部工具条常驻：`+段落 +标题 +图片 +好物卡 +引用 +分割线 | 📥素材 ⚠️声明 📄模板 👁预览`

**放弃的富文本能力**：加粗、斜体、文字颜色、居中。理由：token 化后详情页需逐一实现渲染，成本高而对「食养图文」阅读体验提升极小。**标题 + 图片 + 引用 + 分割线已足够撑起公众号式排版。**

**自动保存**：正文/标题变更后 3s 防抖 → `updateArticle`（草稿态）。顶部显示「已保存 14:32」。

**预览**：复用 `article-detail` 渲染管线（传 `preview=1` 从内存读，不落库）。

### 2.4 图文模板库（4 套）

点「模板」直接把块数组填进编辑器（**替换而非追加**，需二次确认）。

1. **美食攻略**（主推）：标题 → 导语（季节/日常饮食感悟）→ 图片 → 段落×2 → `[[hr]]` → 好物卡占位 → `[[disclaimer]]` → 结尾引导
2. **食材选购指南**：标题 → 选购要点段落×3 → 图片 → 好物卡占位 → `[[disclaimer]]`
3. **人群膳食参考**：标题 → 适用人群说明 → 引用（膳食建议）→ 段落 → 好物卡占位 → `[[disclaimer]]`
4. **生活见闻**：标题 → 时令场景段落 → 图片×2 → `[[disclaimer]]`

**创作中枢原有的「探店推荐 / 美食攻略 / 购物心得 / 生活见闻」四个 chip 直接映射到这 4 套模板**（探店推荐→美食攻略、购物心得→食材选购指南），保持 UI 不变。

⚠️ 模板正文**一律不含任何功效词**，全部使用「日常膳食搭配参考」话术。

### 4.2 需补（P1，激励闭环的地基）

```sql
-- 好物卡点击
CREATE TABLE article_product_clicks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  article_id uuid NOT NULL,
  product_id text NOT NULL,
  user_id uuid,
  created_at timestamptz DEFAULT now()
);

-- 订单归因
ALTER TABLE orders ADD COLUMN IF NOT EXISTS source_article_id uuid;
```

## 八、一句话总结

你这两份文档的**方向对、定位错、假设有硬伤**：

- **对的**：内容种草 → 好物卡 → 下单 → 佣金，这条锁客链路是对的，且 `article-fetch` 已经写好了没人用，捡起来就是加分项；
- **错的**：把「微传媒」当独立模块建，会造出两套编辑器和两套内容列表，用户必迷路——降维成「创作中枢里的一个入口」即可，能力一点不少；
- **硬伤**：小程序没有对外 URL，「复制链接发朋友圈」做不出来，必须换成「海报 + 小程序码」；而现在海报**没有码**，等于朋友圈这条路是废的；
- **真正的命门**：归因链断了三处，「发文章能赚钱」现在只是句口号。修好归因 + 做出侠客数据看板，比多加十个编辑器按钮有用得多。
