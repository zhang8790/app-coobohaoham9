## 二、逐项核查证据

### 1. 构建与体积 ✅
- 实跑 `taro build --type weapp` → **EXIT=0**，产出 `dist/app.json`。
- 主包根 JS 实测：common 581K + taro 224K + vendors 149K + app 8K + babelHelpers 5.5K ≈ **969KB**，远低于微信 1.5MB 主包硬限。
- 仅 2 个 Vite chunk 警告（`supabase.ts`/`api.ts` 同时被动态+静态 import），不影响运行。
- 9 个分包 + `lazyCodeLoading:'requiredComponents'` 维持生效。

### 2. 类型检查 ⚠️（低）
- 实跑 `tsgo -p tsconfig.check.json` → **85 个错误**，与历史（159→85）完全一致、无新增。
- 分布：`TS2322`(55) 本地类型 vs Supabase 生成类型不一致、`TS2339`(15)、`TS2353`(5)、`TS2345`(5)…
- **关键事实**：Taro 用 Babel 转译，**不读取 `tsconfig.check.json`**，类型错误不阻断小程序运行（已多次验证 build EXIT=0）。
- 清理建议：需系统性对齐 `src/db/types.ts` 与 Supabase generated types，工作量大、运行零收益，建议独立专项或接受。

### 3. 登录 AuthContext ✅
- `getSessionWithTimeout`/`getUserWithTimeout` 均 `Promise.race` + **8s 超时**（L54-69），杜绝永久挂起。
- `cancelled` 标志（L51/73/84/107/120）防卸载后 setState；`onAuthStateChange` 在 cleanup 中 `unsubscribe`（L119-132）。
- 坏 token（refresh_token 失效/被吊销）主动 `signOut()` + 回干净登录态 + toast 引导重登（L85-94/97-103/106-116）。
- 测试账号分支（force-login / 1856 / 1870）全被 `process.env.TARO_APP_LOCAL_DEV === 'true'` 门控 → 生产构建 tree-shake 消除，无泄露风险。

### 4. 行囊 cart 闪烁 ✅（此前修复）
- `cart/index.tsx` L22-51 **真实实现** `inflightRef`（并发去重）+ `ignoreNextReloadRef`（自触发抑制）。
- `bumpCartCount` 自触发（`+/-`/删除）经 `ignoreNextReloadRef` 抑制，不再整页 `setLoading` 重 fetch 闪烁（L83/88/100）。

### 5. 门店中心加载中 ✅（此前修复）
- `merchant/merchant-center/index.tsx` L61-64：`Promise.race([getUser(), 8s 超时 reject])`，≤8s 必退出 loading；超时走 catch 兜底返回 `{data:{user:null}}`。
- L133 `(r:{data?:any[]})` 类型修正、骨架含「返回侠客」按钮，避免用户卡死。

### 6. 支付资金安全 ✅
- **P0 修复**：倒计时超时取消订单带 `status:'pending_pay'` 守卫（L347-358）——已支付/已金豆支付/已取消订单不被覆盖。
- `loadData` 用 `[]` 依赖（L329），注释明确规避 `router.params` 引用不稳定导致的无限重渲染死循环（同源 cart 陷阱，已正确处置）。
- 下单前 `verifyProducts(loadedItems)` 预校验（L321），拦截已下架/无价/售罄，避免点到 `createOrderV2` 才报 `INVALID_PRODUCT`。
- 金额计算用 `toFixed4` 防浮点误差（L303/317）。

### 7. 食养合规红线 ✅
- **免责声明已挂载**：`food-scan`、`ComprehensiveSafetyReport`、`profile-analysis`、`index`(4处)、`mine/health-profile`、`FoodSafetyPanel`(食材食养段 L117)。
- **shield 覆盖**：`src/utils/compliance/shield.ts` 的 `shieldCopy()` 在关键动态文案入口调用（食养分析/推荐/报告卡）。
- **违禁词扫描**：治疗/治愈/疗效/降血压/降血糖/排毒/抗癌/根治/处方… 在面向用户食养文案中**无残留**；命中项均为情绪语境（category-emotion/emotionEngine 的"情绪治愈"标签，非医疗宣称，合规允许）。
- **已纠正误判**：`food/scan-result` 实为"扫码购物"结果页（条码→商品，价格/加购），非食养分析页，无需免责声明/shield。

### 8. 密钥与硬编码 ✅
- 源码**无 service_role key**（grep 命中 `service_role` 均为架构注释）。
- 仅有项目引用 URL `https://pyqgsxcjmijtbstwthbn.supabase.co` 在 `api.ts` L2557-2558 硬编码（非密钥，可接受；建议后续抽环境变量）。

## 三、轻微问题（不阻断，建议清理）

### A. 调试日志残留（中）
- `src/db/api.ts` 高达 **139 处** `console.*`，含合法 `error/warn`（错误/兜底日志）与调试 `log` 噪音（如 L300-301 把门店列表整个 dump）。
- 生产建议：保留 `error/warn`，剥离 `log` 调试输出（可用环境变量门控或打包期 strip）。
- 影响：仅日志噪音，不影响功能/性能显著。

### B. FoodSafetyPanel 配料安全段缺免责声明（低）
- `SHIYANG_DISCLAIMER` 仅出现在 L117「食材食养」段；L28-72「配料安全」段（additive 风险等级判定）无免责声明。
- 配料安全段偏事实判定（风险白/黄/黑），但同属食养参考范畴，建议补一行免责以收紧合规纵深。

### C. AuthContext context value 每次渲染重建（低/性能）
- `signIn*` 等方法未 `useCallback`，`value={{...}}` 每次 AuthProvider 渲染重建 → 消费者在 user/profile/loading 变化时重渲染。
- 实际 bounded（仅 AuthProvider 自身状态变化才触发），非 correctness bug，可后续 `useCallback` 优化。

### D. 85 个类型债（低）
- 见 §2。运行零影响，清理需对齐类型定义，投入产出比低。
