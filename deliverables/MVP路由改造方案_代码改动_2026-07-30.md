# MVP 路由改造方案：代码怎么动

> 时间：2026-07-30
> 目的：把 72 个页面的来店有喜，改造为「配料安全扫描」单点 MVP
> 原则：**不动业务逻辑，只动路由和入口**——扫描引擎、食品分析组件、推荐逻辑全部保留复用

---

## 一、改造总览

| 改动类型 | 数量 | 说明 |
|---------|------|------|
| TabBar 重排 | 1 处 | 把「食品扫描」顶为默认首页 |
| 路由隐藏 | 若干 | 移除入口，代码不动 |
| 新增引导页 | 1 个 | MVP 专用大扫描框首页（可复用 food-scan 改） |
| 分包配置 | 2 处 | 商家/管理后台分包暂时不注册（减小主包体积） |

---

## 二、TabBar 改造（最小改动方案）

### 方案 A：替换首页（推荐，最小改动）

把 `pages/index/index`（当前首页）的内容替换为「大扫描框」，
其余 TabBar 不变。风险最低，代码量最少。

```typescript
// app.config.ts 改动
const pages = [
  'pages/food/food-scan/index',   // ⭐ 改为默认首页（大扫描框）
  // 'pages/index/index',           // ← 注释掉或移到最后
  'pages/explore/index',
  'pages/cart/index',
  'pages/user/index',
  'pages/login/index',
  'pages/product/index',
  'pages/store-home/index',
  'pages/payment/index',
  'pages/payment-result/index',
  'pages/order-center/index',
  'pages/search/index',
]
```

**推荐理由**：
- `food-scan/index.tsx` 本身就是一个完整页面，直接当首页即可
- 代码已有「文本粘贴 / 拍照识别 / 扫条码」三个入口，天然适合首屏
- 无需新建文件，改动量最小

### 方案 B：新建 MVP 首页（如果方案 A 不够干净）

如果想把首页做得更纯粹（只有扫描框，其他全部去掉），

**新建** `src/pages/mvp-home/index.tsx`：

```
MVP 首页逻辑：
1. 大扫描框（粘贴配料 / 拍照 / 扫条码）—— 主入口
2. 历史记录入口（扫过的商品）
3. 底部：一个小按钮「进入完整版」（进方案 A 的全功能页面）

这个页面不依赖用户登录，扫码即用。
```

> 建议先用方案 A 验证，方案 B 作为后续迭代选项。

## 三、入口隐藏清单（不改代码，只移入口）

以下入口在 MVP 阶段从 TabBar / 首页 / 个人中心移除，但**代码保留**，验证成功后随时放回：

### 3.1 TabBar 入口（已在上文改动）

| 原始 TabBar | 改动 | 原因 |
|------------|------|------|
| 首页（index）→ 替换为 food-scan | ✅ | MVP 唯一入口 |
| 自营（explore）→ 暂时隐藏 | 建议隐藏 | 避免分散注意力；验证期专注扫码 |
| 购物车（cart）→ 保留 | — | 扫完加购必须用到 |
| 我的（user）→ 保留登录/订单 | 精简 | 移除「健康豆/分销/商家入驻」等次级入口 |

### 3.2 用户中心（`pages/user/index`）待精简项

| 原始入口 | 建议动作 | 说明 |
|---------|---------|------|
| 健康豆余额 | **移除 Tab 展示** | MVP 阶段无关，保留代码 |
| 优惠码/分销 | **移除** | 二级分销已砍，暂不放回 |
| 食养自测（体质测试）| **移除** | 不是 MVP 核心功能 |
| 领取优惠券 | **保留** | 促销用 |
| 订单管理 | **保留** | 核心交易链路 |
| 设置 | **保留** | 必要 |

### 3.3 子分包入口（仅路由保留，入口移除）

| 子分包 | 路由保留 | 入口移除位置 | 说明 |
|--------|---------|------------|------|
| merchant（商家入驻/后台） | ✅ 保留 | user 中心 / 商家入驻入口 | MVP 自营，不开商家入驻 |
| admin（管理后台） | ✅ 保留 | user 中心 / 管理入口 | MVP 阶段只需基本管理 |
| content（内容中心/UGC） | ✅ 保留 | user 中心 / explore Tab | 内容不是 MVP 核心 |
| trade（提现/分佣） | ✅ 保留 | user 中心 / 健康豆页面 | 二级分销已砍，但结算逻辑可能复用 |
| marketing（营销活动） | ✅ 保留 | 首页 / explore Tab | MVP 阶段不做活动运营 |

## 五、新增：MVP 引导落地页（可选）

**触发时机**：用户扫完一个「平台不卖」的品类后

**逻辑**：当 `recommend.length === 0` 时，展示：

```
┌──────────────────────────────────┐
│  配料解析完成                      │
│  评级：A · 含限量成分              │
│                                  │
│  这款商品我们暂时没有              │
│  更安全的替代品上架                │
│                                  │
│  [ 告诉我想上什么 ] ← 反馈入口    │
│  [ 继续扫下一款 ] ← 回到扫描页    │
└──────────────────────────────────┘
```

**目的**：
- 收集用户需求（"你想让我上什么货？"）
- 避免扫完空白体验 → 用户流失
- 用户反馈 → 反哺选品决策

## 七、分阶段放回计划（验证后再动）

| 阶段 | 信号 | 放回模块 |
|------|------|---------|
| 验证成功 | 扫码 UV > 1000/周 + 转化 > 3% | 购物车 → 商品详情 → 订单 |
| 验证成功 + 货品扩充 | SKU > 100 + 周复购率 > 10% | 商家入驻（开放少量精选商家） |
| 验证成功 + 内容起量 | 小红书笔记 > 20 篇 +UGC 出现 | 内容中心（UGC 配料评测社区） |
| 长期 | 月活用户 > 1 万 | 情绪匹配导购、节气食盒、食养自测全放回 |

## 八、风险与注意事项

| 注意事项 | 说明 |
|---------|------|
| **不要动业务逻辑** | 只改入口和路由，分析引擎/数据库/云函数全部保留原样 |
| **保留所有路由** | 隐藏入口 ≠ 删除代码，未来放回时不需要重新开发 |
| **登录态处理** | MVP 首页不强制登录，但加购/下单需要，检查 `useAuth` 在 food-scan 中的使用情况 |
| **小程序审核** | 首页大改后重新提交审核时，备注填写「功能优化，无新增类目」 |
| **百度 OCR** | 如果未配置，拍照按钮会走文本粘贴兜底；建议提前配置好再上线（体验差异明显） |
