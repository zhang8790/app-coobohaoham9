## 2. 打款通道（关键分叉，需拍板）

佣金提现的"钱怎么到用户手里"有两条路：

- **方案 1 · 人工打款（推荐，合规风险低）**
  - 沿用现有 `adminApproveWithdrawal`：审核通过 → 扣 `commission_balance` → 标记 `paid`。
  - 财务线下通过**银行转账 / 微信转账**给个人（劳务报酬打款，口径清晰）。
  - 零新增支付接口、零微信权限申请；监管视角是"平台对个人的推广服务费打款"。
  - 前端仅需在审核页展示"已到账/打款中"状态（已有 status 枚举 pending/paid/processing）。

- **方案 2 · 微信自动转账到零钱**
  - 新增 `user-commission-payout` Edge Function，调微信支付「商家转账到零钱」（原企业付款到零钱）。
  - 需商户号开通该权限 + 实名/限额 + 失败重试；开发量与合规审查显著更大。
  - 用户体验好（审核通过自动到账），但二清/合规边界需法务确认。

## 3. 提现比例分叉（次要，可默认）

- **保持 50% 可提现**（当前后端 `COMMISSION_CASH_RATIO` 默认 0.5）：一半现金佣金 + 一半健康豆，最稳，无需动 distribute-commission。
- **100% 可提现**（改 `COMMISSION_CASH_RATIO=1.0`）：佣金全进 `commission_balance`，不再发健康豆那半。需确认买家确权返利（bfFinal）是否仍走健康豆——若改则影响消费抵扣体验。

> 默认建议：**保持 50%**，与 2026-07-29 已上线模型一致，改动最小。

## 4. 合规红线（启用提现后必须保留）
- 仍限**两级**（L1 直推 + L2 间推），不裂变、不团队计酬。
- 佣金基数来自**真实消费** `net_amount`（已有）。
- 提现实名 + 身份证核对（表单已含）。
- 明示"推广佣金为劳务报酬，用户自行纳税申报"（line 456，保留）。
- 全站禁「躺赚 / 被动收入 / 团队计酬 / 分销佣金 / 团队业绩 / 飞轮」等词（统一术语：推广佣金、健康豆）。

## 6. 影响面 / 风险
- **低风险**：前端接线不改资金模型；`applyWithdraw`/`adminApproveWithdrawal` 已线上验证逻辑。
- **注意**：`commission_balance` 从 2026-07-29 起已在累加，开放提现即意味着历史累计的可提现佣金可被用户取出——需确认财务已预留对应资金。
- **不要动**：买家确权返利（bfFinal）仍走 `tb_balance` 健康豆（消费用，不可提现），与佣金提现正交。
